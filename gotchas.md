# Gotchas

- PR #24's nine commits already exist on `main` as patch-equivalent commits; it was closed as superseded on 2026-08-08.
- Docker dependencies live in a locked `/opt/venv` copied between identical Python base images. Keep both stage images aligned and keep production installs tied to `uv.lock`.
- Audit this project's environment with `uv run --locked --with pip-audit pip-audit`; `uvx pip-audit` audits its isolated tool environment and can give a false clean result.
- NWS `/alerts/active` accepts the `point` and `status` filters used here, but rejects `limit`. Validate alert response shape and preserve upstream failures as errors; never cache them as a valid zero-alert result.
- Unknown-city paths contain user input. Keep their 404 responses in a plain-text context unless a template escapes the value explicitly.
- Parse location once for the whole page. Independent widget defaults currently mix data from several cities on one route.
- Frontend JavaScript unit tests run through pytest and require `node` on `PATH`; they use Node's built-in test runner and need no npm packages.
- The widget catalog is the only source for widget URL names; do not recreate aliases or host mappings in components.
- Public theme names are `blue|light|eink`; normalize legacy aliases before applying any styles.
- Keep the hourly chart, temperatures, icons, and times on the same centers for the actual number of rendered hours. Separate flex rows produce different widths and independent scroll positions, especially in eInk.
- Hour labels use zero-padded `%I%p`; strip only the leading padding with `lstrip('0')`, because replacing every zero corrupts labels such as `10pm`.
- Bump both service-worker cache names whenever a cached UI asset changes, or cache-first clients can keep the prior release.
- Size full-width pages against the layout viewport with `width: 100%`; `100vw` includes the desktop scrollbar and can create horizontal overflow.
- Give vertical space between adjacent eInk blocks one owner; stacked margins hid usable screen area in current conditions.
- `templates/weather.html` loads its scripts as classic scripts, which share one global scope. A top-level `function`, `const`, or `let` in one file collides with the same name in another, and the second file dies at parse time before a single statement runs — taking every `customElements.define` in it with it. Keep library files wrapped in an IIFE and export through one namespace object. `tests/js/page-script-scope.test.js` guards this; suites that `require()` these files cannot, because CommonJS gives each module its own scope.
- `.weather-container` is a flex column and its `gap` is the only owner of space between blocks. Widget wrappers carry no `margin-bottom`; adding one double-spaces the page.
- `.stat-band` is `display: contents` in blue and light so `order` composes the phone layout, and a bordered flex box in eInk. `.sky-pair` is a grid in every theme — giving it `display: contents` would strip its `order` and its columns.
- The hourly chart is a fixed `viewBox="0 0 1000 H"` with `preserveAspectRatio="none"`. Do not reintroduce `getBoundingClientRect` or a resize observer, and never put a circle in that SVG: the two axes scale differently, so it renders as an ellipse. The current-hour marker is a positioned HTML element.
- Precipitation bar columns carry no grid gap; the visual gap is inset padding on the cell. A grid gap walks the column centers away from the evenly divided SVG width.
- The lunar cache key includes latitude and longitude. Moonrise is location-dependent, and the old hour-only key served one city's moonrise to every other.
- `[data-theme="eink"] .weather-container` needs a resolved `height: 100vh`. It is a flex column, and `flex: 1` on the hours card distributes *free* space — a content-sized column has none, so the card collapses to its content and the `flex: 1` chart inside it measures exactly 0px. The page footer and the PWA install button also hide in eInk: the footer is a sibling of the container and would push an 800x480 panel into a scroll.
- A `.precip-cell` pads both its sides, so the visible gap between two adjacent bars is **twice** the cell padding. The grid gap stays 0 so column centres stay on the evenly divided SVG width; only the padding sets the gap's size.
- An element with `display: contents` has no box. `getBoundingClientRect()` returns 0x0 at the origin and it consumes no flex gap, so measuring the space around `.stat-band` in blue or light reads a gap that is not there. Enumerate the container's visible children instead.
- Below 640px the eInk panel hides `.three-temps` and stacks `.stat-band`. The bars grid has a ~233px min-content floor from its `auto 7.5rem auto` columns and a 320px panel leaves the row 149px. Note the band has only two flex children — `current-weather` and `.sky-pair` — so `flex-wrap` on the band cannot relieve an overflow that happens inside `current-weather`'s shadow root, which is where temperature, the text column and the bars all live.
- A dot centered with `transform: translateX(-50%)` still contributes to `scrollWidth` in Chrome. `.three-temps-scale` therefore drives both its wet dot's `left` and the fill's `width` from one `--wet-offset`, whose travel runs between the dot centers rather than the track edges — where the fixed feels and air dots already sit. JS sets only the unitless `--wet-position`, so the dot diameter stays defined once, in CSS.
- The eInk high and low row wraps. Every other width in that band is pinned to the mock, and the row's own width is data-bearing: the mock's `HIGH 23° LOW 9°` fits 149px, while `HIGH 88° LOW 73°` needs 162. On wide-data days the band is 22px taller and the hours chart 22px shorter than the mock.
- Adding a `timedelta` to an aware local datetime moves the **wall clock**, not the instant — the UTC offset is only resolved later, by `astimezone`. Sampling a day as `local_midnight + timedelta(hours=h)` therefore gives an uneven grid: on a fall-back day one bracket spans two real hours, and any bisection inside it searches only the repeated hour's first pass. `calculate_moon_times` samples and bisects in UTC over the day's true length and converts only the final crossing back. Do not assume that length is a whole number of hours: `Australia/Lord_Howe` shifts by 30 minutes, so its transition days run 23.5 and 24.5 and a `round()` on the span drops a real crossing. Close the sample list on the day's end instant instead, and clamp the rounded crossing below it so a time in the last half minute cannot carry the next day's date. Bugs of this shape do not show as exceptions; they show as a crossing reported at the last minute of its wall-clock hour.
- When you replace a hard-coded value with a theme token, the test that guarded the *rendered* value must move with it. Asserting `border: 2px solid var(--card-border)` alone proves the reference exists and nothing about the contrast — assert the token's definition in the theme block too, or the guarantee quietly drops to zero.
- `.github/workflows/lint.yml` installs its linters with `uv add --dev ruff mypy bandit` — **unpinned**. Each run enforces whatever ruff is newest, so Code Quality can go red on code nobody touched; it has failed every run since 2025-07-25. Checking locally with a pinned older ruff is not checking what CI checks: `ruff@0.6.4` printed "All checks passed" against a tree CI's `ruff@0.16.6` gave 17 violations, because `PLC0415` and `PLR0917` postdate 0.6.4. Run `uvx ruff@latest check .`, and against an already-red baseline count violations on the merge base and on HEAD and diff the lists — what the branch *added* is the number that matters. The formatter drifts too: 0.16.6 reformats Python fences inside markdown and dedents class-method excerpts into top-level functions, which corrupts the plan and spec docs.
- The daily chart draws in pixel space, unlike the hourly one: its markers are circles, and a `preserveAspectRatio="none"` viewBox would scale the axes differently and render them as ellipses. Pixel space costs a `ResizeObserver` — weather data refreshes only every ten minutes, so without one a resized chart keeps the width it was drawn at for the rest of that interval. `.daily-forecast` keeps `gap: 0` for the same reason `.precip-cell` does, and the chart plots only the days the grid actually shows, read back with `getComputedStyle` so the 640px breakpoint stays in the stylesheet: below it the grid renders four of seven columns, and a chart that always drew seven put three markers past the right edge of its own SVG.
- Both temperature charts scale their y-axis through `temperatureScale`, which never lets the axis span less than `MIN_TEMPERATURE_SPAN` (10°F); a narrower forecast centres inside that band. Scaling to the data alone is what a chart library does, and it is wrong here: an overnight of `77 76 75 75 75 75 76 77` is weather doing nothing, but ranged to its own 2° it draws the same full-height cliff as a 40° cold front. The floor also subsumes the flat-forecast case — a single repeated temperature lands at the band's midpoint by the same arithmetic — so neither chart needs a `range === 0` branch. A test that feeds a range under 10° and asserts a point at the plot edge is asserting the old behaviour.
